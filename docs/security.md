# 安全边界

Viva 0.1.0 是单用户的本地工作台。它没有多用户登录，不能称为企业生产就绪。同一台机器上能读取数据目录的人，就能读取知识库。数据库没有应用层加密。

默认只监听 `127.0.0.1`。其他地址必须同时设置 `VIVA_ALLOW_NONLOCAL=1`。不信任 `X-Forwarded-For`。

变更请求需要本机令牌和 `x-viva-request: 1`。Cookie 是 `HttpOnly`、`SameSite=Strict`。来源正文、检索片段和渠道消息都当不可信数据，不能改自动驾驶或自动发布。自动发布和 GitHub 写接口默认关闭。渠道出站默认关闭。

URL 抓取只允许 http/https，手动跟随重定向，并在连接前拒绝回环、私网、链路本地、共享地址空间、组播和 `169.254.169.254`。本地文件拒绝越出根目录的符号链接，单文件超过 512 KiB 会跳过。Webhook 正文限制 256 KiB。

日志和审计调用 `redact`。模型 API 不把密钥返回给界面。默认备份不复制 `secrets.json` 和 `token`。

飞书入站校验签名和时间窗，并用事件 id 去重。钉钉入站校验 HMAC 和时间窗；加密回调返回 `decrypt_pending`。

DeepSeek Harness 的安全说明写明它可以执行模型生成的命令，而且沙箱不是可靠边界。dsh-superagent 的执行文档写明 worker 以操作系统用户身份运行，目录包装不是安全边界。Viva 不启动这些会话，也不把版本号匹配写成已经集成。

残留风险：检查 DNS 之后再连接，仍有 DNS 重绑定的时间差。0.1.0 没有把连接钉在已经检查过的地址上。不要把 Viva 当成对外的抓取代理。
